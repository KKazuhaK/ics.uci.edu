1. 为什么 UI 实现很重要

幻灯片用一个简化的产品设计流程来引入本课：Ideate（构思）→ Refine（打磨）→ Design（设计）→ Implement（实现）→ Test（测试）→ Deploy（部署），并且 Deploy 有一条箭头回到 Ideate（这是一个循环，而不是一条直线）。本课聚焦在 Implement 这一步。

用户界面实现：

  • 有能力把想法变成现实；
  • 往往决定了设计决策和时间线，不论好坏；
  • 无法回避：要么你自己来实现，要么你得和负责实现的同事沟通。

今天的界面实现是什么？ 通常是 HTML、CSS 和 JavaScript，以及建立在它们之上的各种框架。幻灯片上的 logo 墙有：Angular、Bootstrap、React JS、Backbone.js、Meteor、Ionic、Node、Vue.js、Ember。其中本课作业会用到 Bootstrap、Angular 和 Ionic（见第 7 节）。

这就引出了本讲的核心问题：语言和开发框架有那么多，为什么大多数人都用 Web 工具？ 第 2–5 节的历史会逐步构建答案，答案在第 6 节给出。

2. Weiser 与计算的三次浪潮

《The Computer for the 21st Century》，作者 Mark Weiser，Xerox PARC 的首席科学家，1991 年发表于 Scientific American。这篇文章提出了“Ubiquitous Computing”（普适计算）这个词。幻灯片称它既是回顾性的（reflective，回看计算是如何发展的），也是推测性的（speculative，设想接下来会发生什么）。

本讲把计算史划分为三次浪潮，每一次由“多少人共用多少台计算机”来定义：

浪潮 幻灯片中的年代 人 : 计算机 幻灯片标签
1. 大型机计算（Mainframe computing） 1940s–1960s 多人共用一台计算机 "Many to one"
2. 个人计算（Personal computing） 1970s–1990s 一人一台计算机 "One to one"
3. 普适计算（Ubiquitous computing） 今天 一人多台计算机 "One to many" 
flowchart LR
  w1["1 · 大型机计算 — Many to one"] --> w2["2 · 个人计算 — One to one"] --> w3["3 · 普适计算 — One to many"]

💡 核心要点：many-to-one、one-to-one、one-to-many 这三个比例，是本讲历史部分的一句话总结。

🔗 延伸阅读：Weiser, "The Computer for the 21st Century" (ACM DL)

3. 第一次浪潮：大型机计算

3.1 Harvard Mark I 与批处理

Harvard Mark I 是幻灯片中的大型机范例：

  • 体积大：宽 55 英尺，高 8 英尺，重 5 吨。
  • 价格高：仅外壳在 1945 年就花了 50,000 美元。
  • 曾用于曼哈顿计划（Manhattan Project）中计算内爆（implosion）。

大型机通过批处理（batch processing）工作：

  1. 把程序写在穿孔卡片上。
  2. 排队等计算机轮到你。
  3. 运行程序，祈祷它能跑通。
  4. 如果不行，修改后再等下一次轮到你。

结果：交互性很差。许多人共用一台机器——“many to one”。

3.2 Vannevar Bush 与《As We May Think》

Vannevar Bush：MIT 教员；主管国家国防研究委员会（National Defense Research Committee），该委员会领导了曼哈顿计划；战后帮助确立了美国国家科学基金会（National Science Foundation）的使命：

  • 联邦政府资助大学；
  • 大学从事基础科学研究；
  • 这些研究有益于经济和国防。

他的文章《As We May Think》（Atlantic Monthly，1945）在一定程度上规划了战后的科研议程。与 Weiser 的论文不同，它是推测性的，而非回顾性的——它设想的是当时还不存在的设备。

3.3 Memex（1945 年的推测性设计）

文中设想的设备是 Memex，一台桌子大小的机器，用于：

  • 跨设备、跨来源地链接信息——也就是超文本（hypertext），Web 的基础；
  • 对一手资料进行笔式批注。

幻灯片里的动画来自 1995 年（在 SIGIR 上展示），而不是 1945 年——Memex 从未被造出来。

3.4 命令行界面（1960s）

  • 最初用在连接到大型机的终端上；后来被整合进个人计算（Unix 等）。
  • 人可以根据输出来改变执行。
  • 这使得实时调试成为可能——相比在穿孔卡片时代排队等候，是很大的进步。

3.5 Doug Engelbart 的 NLS（1968）

1968 年对 NLS（“oN-Line System”）的演示展示了：

  • 第一个可用的超文本系统（把 Memex 的想法真正做了出来）；
  • 鼠标的发明；
  • 简单图形（更早的系统就有，但这里是在一个完整系统中使用）；
  • 还有其他想法：和弦键盘（chording keyboard）和远程协作。

反响不一：有人认为他是“造假”，也有人觉得无关紧要，因为“终端也能做同样的事”。Engelbart 于 1997 年获得图灵奖。

⚠️ 易错点：要分清年代和角色——Bush 设想了超文本（Memex，1945）；Engelbart 做出了第一个可用的超文本系统和鼠标（NLS，1968）。

🔗 延伸阅读：Bush, "As We May Think" (The Atlantic, 1945) · Memex 动画（1995，YouTube） · Engelbart 1968 年演示

4. 第二次浪潮：个人计算

个人计算最早由 Xerox 推出：

系统 年份 幻灯片中的说明
Xerox Alto 1973 鼠标、和弦键盘
Xerox Star 1981 软件在窗口中运行；带图标的桌面，用来在文件和程序之间切换；“super slow!”（超级慢！）
Apple Macintosh 1984 （截图：带窗口、文件夹、计算器的 Mac 桌面）
Windows 1.0 1985 （截图：平铺窗口——文件列表、Reversi、时钟、Write）
Windows 3.0 & 3.1 1990 & 1992 窗口化成为主流；加入了纸牌（Solitaire）、扫雷（Minesweeper）和 FreeCell——一个训练鼠标操作的小花招
Mosaic 网页浏览器 1993 最初面向 Unix，后来移植到 Mac 和 Windows；“第一个”图形化网页浏览器

Xerox 的机型在商业上并不成功：价格依然昂贵，而且应用太少。关于浏览器：Microsoft IE 出现于 1995 年；Apple 直到 2003 年的 Safari 才有自己的浏览器。

此时一个人有了一台计算机——“one to one”。

🔗 延伸阅读：Xerox Star 演示（1981，YouTube）

5. 第三次浪潮：普适计算

Weiser 推测人们会与三种类型的计算机交互，并且设备会是共享所有权：

Weiser 的术语 尺度 类比 今天（按幻灯片）
Tabs 英寸级 便利贴（post-it） 手机和手表
Pads 英尺级 纸 平板和笔记本
Boards 码级 白板 交互式投影仪？智能电视？增强现实（AR）？

这与我们今天使用的设备大体吻合（幻灯片展示了手机、平板、智能电视、笔记本、智能手表和 VR/AR 头显）。最大的偏差是：设备所有权的观念依然很强，而不是共享设备。

此时一个人使用多台计算机——“one to many”。

6. 为什么 Web 工具成为标准

开头那个问题的答案：普适计算在很大程度上就是 Web 工具成为当前界面开发标准的原因。

画面是这样的：一个人，多台设备，通过云同步（手机、智能音箱、手表、平板、台式机、笔记本都连到同一个云）。Web 技术栈正好与之对应：

任务 Web 工具
向云端发送数据并接收数据 HTTP 请求——JavaScript 很早就提供了相关工具
渲染这些数据 HTML
给它们设置样式 CSS

Web 工具成为标准的原因（幻灯片 42）：

  • 几乎每个平台都需要与云系统通信。
  • 大多数平台需要一个 Web 浏览器，方便人们访问网站。
  • 共用的编程语言和开发环境能带来高效的工作方式。
  • 开发者可以一次编写，部署到多个平台——并且希望能针对设备定制样式和功能。
  • “还有其他原因吗？”——留作课堂讨论。

💡 核心要点：“针对设备定制样式和功能”就是响应式设计（responsive design）的雏形，A1 以及 Lecture 3–4 会讲到。

7. 课程目标与作业

7.1 课程目标

学完本课后，你应该能够：

  • 用 HTML、CSS 和 JavaScript 构建对屏幕尺寸和用户能力敏感的网页；
  • 遵循设计最佳实践，用 TypeScript 框架构建移动应用；
  • 利用外部 Web API（数据库、信息源）和设备资源（照片、传感器）来降低开发负担并实现新功能；
  • 针对给定的设计，选择合适的设备来支持，并选择合适的开发框架。

7.2 五个作业

# 标题 技术 学习目标
A1 Responsive Portfolio HTML、CSS（概览页上有 Bootstrap logo） 熟悉 HTML 和 CSS（所有 Web 设计的基础）；应用响应式（responsive）设计——适配屏幕尺寸和方向
A2 Runkeeper Tweet Report JavaScript 和 TypeScript 熟练使用 JavaScript；用 JavaScript 库做可视化和交互

7.3 这是一门什么样的课

  • 这是一门编程量很大的应用型课程：大约一半讲实现技术，另一半讲指导设计与开发的理论概念。
  • 原则和语言只做高层次的讲解；API 和包的具体细节需要你自己学。课程团队乐意帮忙，但并没有用过每个 API 的每个方面。
  • 往届学生的评价（幻灯片引用）：你会学到很多（“在上这门课之前，我从没尝试过 Web 开发……现在感觉非常有信心”），但会很难（“对于从未接触过 JavaScript 和应用开发的人来说，作业有些挑战”）。
  • 期望很高，但课程团队关心学生也愿意倾听——有情况就告诉他们。要“全情投入”；如果你还没准备好投入，请现在就退课，把名额让给别人。

9. 课堂问题与演示（附解答）

9.1 问题 1：为什么 Web 工具是界面开发的标准？（幻灯片 6 和 38）

幻灯片 6：“There are lot of languages and development frameworks. Why do most people use web tools?”（语言和开发框架有那么多，为什么大多数人都用 Web 工具？）——在幻灯片 38 以 Think & Share 的形式再次提出：“Why are web tools now the standard for interface development?”（开放式讨论，没有选项）。

✍️ 先自己试试。

答案（幻灯片自己给出的，p39–42）：普适计算。现在一个人使用多台通过云同步的设备。每个平台都需要和云通信（HTTP 请求，JavaScript 很早就提供了相关工具），而且大多数平台都有浏览器；HTML 渲染数据，CSS 给数据设置样式。共用的语言和环境让开发者可以一次编写、部署到多个平台，并针对每种设备做定制。回到第 6 节。

必记的 5 点
