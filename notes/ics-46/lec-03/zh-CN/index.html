1. 2-Sum 问题：统计操作次数

⬅️ 承接 Lecture 2：2-Sum 活动在 Lecture 2 末尾提出（幻灯片 34，同时介绍了数学模型和波浪号（tilde）记法）；本讲的幻灯片 4 给出了解答。

问题：给定 n 个互不相同的数，有多少个无序数对（“duplet”）的和为 0？暴力解法对每个满足 i < j 的数对恰好检查一次：

int count = 0;
for (int i = 0; i < n; i++) {
    for (int j = i+1; j < n; j++) {
        if (a[i] + a[j] == 0) {
            count++;
        }
    }
}

对于固定的 i，内层循环体执行 n - i - 1 次，所以总共执行 (n−1)+⋯+1+0=n(n−1)/2(n-1) + \dots + 1 + 0 = n(n-1)/2(n−1)+⋯+1+0=n(n−1)/2 次（每个数对一次）。每个循环的判断条件比循环体多执行一次。幻灯片 4 的统计结果：

操作 次数（幻灯片 4） 来源
变量声明 n+2n + 2n+2 count、i，以及每次外层迭代各声明一次 j
赋值 n+2n + 2n+2 count = 0、i = 0、j = i+1 ×n
小于比较 (n+1)(n+2)/2(n+1)(n+2)/2(n+1)(n+2)/2 外层：n+1n+1n+1；内层：n+(n−1)+⋯+1=n(n+1)/2n + (n-1) + \dots + 1 = n(n+1)/2n+(n−1)+⋯+1=n(n+1)/2
等于比较 n(n−1)/2n(n-1)/2n(n−1)/2 每个内层循环体一次
数组访问 n(n−1)n(n-1)n(n−1) a[i]、a[j]：每个内层循环体 2 次
自增 n(n+1)/2n(n+1)/2n(n+1)/2 到 n2n^2n2 i++ ×n + j++ ×n(n−1)/2，再加上 0 次或多次 count++

幻灯片的结论是：“Already becoming too tedious to calculate!”（已经繁琐到算不下去了！）——所以只选一种成本模型（数组访问），并只保留最高次项：暴力 2-Sum 进行 ∼n2\sim n^2∼n2 次数组访问。本讲后面连常数也一并忽略。

n=10 (no pairs)  pairs=0 decl=12 assign=12 less=66 eq=45 access=90 incr=55

⚠️ 易错点：循环判断条件会比循环体多执行一次（最后那次失败的判断）——外层的 < 是 n+1n+1n+1 次，而不是 nnn 次。

2. 渐近分析：Big-O、Big-Ω、Big-Θ

2.1 为什么要“往大处想”（幻灯片 5–7）

幻灯片 6 比较了 f(n)=nf(n) = nf(n)=n、g(n)=4ng(n) = 4ng(n)=4n、h(n)=n2h(n) = n^2h(n)=n2。当 n 很小时，fff 和 ggg 看起来差别很大，hhh 甚至比它们更低（n<4n < 4n<4 时 n2<4nn^2 < 4nn2<4n）。当 n 很大时，fff 和 ggg 相对于 hhh 看起来很相似，而 hhh 的增长速度明显不同。

渐近分析（asymptotic analysis）（幻灯片 7）把运行时间描述为输入规模 n 的函数，并且只关注 n 变大时的增长情况：忽略小的 n（“THINK BIG”）；增长率越慢 = 算法越好。

2.5 情形与增长率（幻灯片 15）

这是两个独立的问题：哪种情形？（最好 / 平均 / 最坏输入）以及增长得多快？（O(1)、O(log n)、O(n)、O(n²)……）。在长度为 n 的数组中做线性查找：

情形 何时发生 比较次数 增长率
最好 目标在第一个位置 1 O(1)
平均 目标在中间 n/2 O(n)
最坏 目标在最后或不存在 n O(n)

⚠️ 易错点：“Big-O = 最坏情形，Big-Ω = 最好情形”是错的。要先确定情形，再给它求界：线性查找的最坏情形是 Θ(n)，最好情形是 Θ(1)。如果不指明情形，它是 O(n) 且 Ω(1)，但没有 Θ。

5. 为什么需要数据结构？

幻灯片 20：数据结构（data structure）组织并存储数据，使所需的操作足够高效（好比杂乱无章的图书馆与分类整齐的图书馆）。评判它的标准是时间和空间复杂度，而且没有放之四海而皆准的结构——所以才有这么多种结构。

幻灯片 21 列出的典型操作：插入、删除、查找、替换，以及遍历、排序、判空。没有哪一种结构能把它们全部做得高效；选择取决于你的数据、你需要哪些操作（以及多频繁），还有技术限制（内存、实时性）。

6. ArrayList（动态数组）

6.1 状态（幻灯片 24–25）

ArrayList（可变长 / 动态数组）是一种从 0 开始编号的线性结构，存放在连续内存中，由一个具有某个容量的底层数组支撑。和数组一样，它支持 O(1) 的按下标访问。它包含三样东西：elements 数组、size（元素个数）和 capacity（已分配的长度）。它会自动分配/释放内存，使用前 size 个格子，满了之后就分配一个更大的数组并把所有元素复制过去。它与 std::vector 相对应。

6.4 扩容时发生了什么（幻灯片 30）

数组已满时，add 会分配两倍容量的新数组，复制全部 n 个元素（这就是 Θ(n) 的部分），释放旧数组，让 data_ 重新指向新数组，然后再存入新元素。指针的变化才是关键，所以这里演示一次：

幻灯片 30 中，对已满的容量为 2 的数组执行 a1.add("!")（演示从扩容那一步开始）。在下面一步步演示（演示获得焦点时，可用 ← / → 键）：

{"title": "幻灯片 30：对已满的 ArrayList 执行 add", "ops": "add(ICS46); add(Rocks); add(!)", "start": 7}

add(index, item) 则是把 data_[index..n-1] 向右移动一格，并且是从后往前（for (size_t i = n_; i > index; --i) data_[i] = data_[i-1];），这样没有任何元素在被移走之前就被覆盖；remove(index) 向左移动，从前往后。

⚠️ 易错点：先复制，再 delete[]，最后再重新赋值——先删除会丢失数据，先重新赋值会泄漏旧缓冲区。

7. 扩容与摊还分析

7.1 策略与最坏情况（幻灯片 36–38）

扩容 缩容
触发条件 向已满的表添加元素 表变为 ¼ 满
动作 容量 × 2 容量 × ½
代价 复制所有元素 复制所有元素

关键问题（幻灯片 38）：add() 的最坏情况是什么？成本模型：插入记 1，复制 n 个元素记 n。所以一次 add 平时的成本是 1，触发扩容时是 n + 1：最坏情况 O(n)。对一连串的 add 来说，这个估计过于悲观——于是引出摊还分析（amortized analysis）。

📘 课外补充：在 ¼ 处（而不是 ½ 处）缩容可以避免抖动（thrashing）——如果在 ½ 处缩容，在边界上交替执行 add/remove 会导致每次调用都要扩容/缩容，每次代价 Θ(n)。

7.2 摊还成本（幻灯片 39）

每次操作的摊还成本（amortized cost） = 一连串 n 次操作的总成本 ÷ n。方法有：聚合法（aggregate）（给总成本 T(n) 求界再除以 n——这里使用的方法）、记账法（accounting）（收取固定价格，存入信用）、势能法（potential）（用势函数存储“能量”）。

💡 关键洞察：摊还 ≠ 平均情形。这里不涉及概率：它是对任意操作序列总成本的最坏情形保证。

7.3 翻倍与每次只增加 1（幻灯片 40–44）

从容量 1 开始，调用 n 次 add。当数组已满时，第 (k+1) 次 add 要复制 k 个元素：

k 0 1 2 3 4 5–7 8 9–15 16
复制成本，×2（幻灯片 40–43） 0 1 2 0 4 0 8 0 16
复制成本，+1（幻灯片 44） 0 1 2 3 4 5–7 8 9–15 16

（每一列的插入成本都是 1；总成本 = 插入 + 复制。）

观察 +1 增长时复制的次数是如何不断累积的——在脑中把 growth 换成翻倍，再与表格对照。在下面一步步演示（演示获得焦点时，可用 ← / → 键）：

{"title": "每次只增加 1：除第一次外，每次 add 都要复制全部元素", "ops": "add(A); add(B); add(C); add(D); add(E); add(F)", "capacity": 1, "growth": "plus1"}
  • 翻倍：复制次数 =1+2+4+⋯+2⌊log⁡2n⌋≤2n= 1 + 2 + 4 + \dots + 2^{\lfloor \log_2 n \rfloor} \le 2n=1+2+4+⋯+2⌊log2​n⌋≤2n（等比数列，公比为 2），插入 =n= n=n，总计 ≤3n\le 3n≤3n → 摊还 O(1)，但是“不均匀”（lumpy）：扩容发生的间隔变为两倍，每次的代价也变为两倍。
  • +1：总计 =n+(0+1+⋯+(n−1))=n+n(n−1)/2=Θ(n2)= n + (0 + 1 + \dots + (n-1)) = n + n(n-1)/2 = \Theta(n^2)=n+(0+1+⋯+(n−1))=n+n(n−1)/2=Θ(n2) → 摊还 Θ(n)。

实测的元素复制次数（初始容量为 1）：

n=17  doubling: 31 copies (2.82353 per add)   +1: 136 copies (9 per add)
n=1000000  doubling: 1048575 copies (2.04858 per add)   +1: 499999500000 copies (500000 per add)

⚠️ 易错点：要说“add 是摊还 O(1)，最坏情况 O(n)”——漏掉“摊还”二字就是错的。

📘 课外补充（Thornton）：摊还 O(1) 对总时间来说没问题，但如果每一次操作都有截止时间（实时控制、60 fps 的游戏），就不行了——一次 O(n) 的扩容就意味着掉一帧。

8. 完整实现

#include <cstddef>
#include <stdexcept>
#include <string>
#include <utility>

template <typename T>
class ArrayList {
public:
    ArrayList() : ArrayList(2) {}                       // slide 26: initial capacity 2
    explicit ArrayList(size_t capacity)
        : data_{new T[capacity > 0 ? capacity : 1]},
          capacity_{capacity > 0 ? capacity : 1}, n_{0} {}

    // Rule of three: we own data_, so copying must copy the buffer.
    ~ArrayList() { delete[] data_; }
    ArrayList(const ArrayList& other)
        : data_{new T[other.capacity_]}, capacity_{other.capacity_}, n_{other.n_} {
        for (size_t i = 0; i < n_; ++i) data_[i] = other.data_[i];
    }
    ArrayList& operator=(ArrayList other) {             // copy-and-swap
        std::swap(data_, other.data_);
        std::swap(capacity_, other.capacity_);
        std::swap(n_, other.n_);
        return *this;
    }

    bool isEmpty() const { return n_ == 0; }
    size_t size() const { return n_; }
    size_t capacity() const { return capacity_; }

    const T& at(size_t index) const { rangeCheck(index); return data_[index]; }

    void set(size_t index, const T& item) { rangeCheck(index); data_[index] = item; }

    void add(const T& item) {                          // append at the end
        if (n_ == capacity_) resize(2 * capacity_);
        data_[n_++] = item;
    }

    void add(size_t index, const T& item) {            // insert, shift right
        if (index > n_) throw std::out_of_range("add: index " + std::to_string(index));
        if (n_ == capacity_) resize(2 * capacity_);
        for (size_t i = n_; i > index; --i) data_[i] = data_[i - 1];
        data_[index] = item;
        ++n_;
    }

    T remove() {                                       // remove from the end
        if (n_ == 0) throw std::out_of_range("remove from empty ArrayList");
        T item = data_[--n_];
        shrinkIfSparse();
        return item;
    }

    T remove(size_t index) {                           // remove at index, shift left
        rangeCheck(index);
        T item = data_[index];
        for (size_t i = index; i + 1 < n_; ++i) data_[i] = data_[i + 1];
        --n_;
        shrinkIfSparse();
        return item;
    }

private:
    T* data_;
    size_t capacity_;
    size_t n_;

    void rangeCheck(size_t index) const {
        if (index >= n_) throw std::out_of_range("index " + std::to_string(index));
    }
    void shrinkIfSparse() {                            // slide 36: halve when 1/4 full
        if (capacity_ > 1 && n_ <= capacity_ / 4) resize(capacity_ / 2);
    }
    void resize(size_t newCapacity) {
        T* bigger = new T[newCapacity];
        for (size_t i = 0; i < n_; ++i) bigger[i] = data_[i];
        delete[] data_;
        data_ = bigger;
        capacity_ = newCapacity;
    }
};

从 ArrayList a1; 开始，预测依次执行下列操作后的内容、size 和 capacity：add("ICS46")、add("Rocks")、add("!")、add(1, "Throws")、add(3, "?")，然后三次 remove()。

9.5 活动 2：摊还分析——每次增加 1（幻灯片 44）

如果 ArrayList 在已满时只多增加 1 个位置，那么它的 add() 的摊还时间复杂度是多少？

解答。 每次 add 摊还 Θ(n)。 每次 add 之前数组都是满的，所以第 (k+1) 次 add 要复制 k 个元素：总计 n+n(n−1)/2=Θ(n2)n + n(n-1)/2 = \Theta(n^2)n+n(n−1)/2=Θ(n2)，再除以 n。翻倍策略的总成本 ≤ 3n，摊还 O(1)。

必记的 5 个要点

  1. Big-O 是上界，Big-Ω 是下界，Big-Θ 两者兼具——当两者不一致时 Θ 不存在。
  2. 情形（最好/平均/最坏）和界（O/Ω/Θ）是两个独立的问题：先确定情形，再给它求界。
  3. 要从公式中读出 Big-O，保留增长最快的项并去掉它的常数（7n−2000=O(n)7n - 2000 = O(n)7n−2000=O(n)）。
  4. ArrayList 的 add 是摊还 O(1)、最坏 O(n)，因为翻倍使复制次数构成一个和 ≤ 2n 的等比数列。
  5. 每次只增加一个常数、而不是乘以一个倍数来扩容，会让 add 摊还 Θ(n)（n 次 add 的成本为 Θ(n²)）。
